🔄 MLOps & n8n

Workflow automation, experiment tracking, and model lifecycle management

Webhook POST /webhook/ml-predict

n8n_prediction_workflow.json — Basic Prediction

Receives prediction request via webhook → forwards to FastAPI /predict → saves result via /save-n8n-result → responds with structured JSON. Timeout: 30 000 ms.

Webhook POST /webhook/ml-predict

n8n_prediction_workflow_extended.json — Extended with Alerts

Full enrichment pipeline: adds risk_label + summary → routes by actor → sends Telegram/Gmail alerts on HIGH_RISK → logs to Google Sheets → optionally triggers /retrain on anomaly. Integrations: Telegram, Gmail, Google Sheets.

Cron — Every Sunday 02:00

n8n_retraining_workflow.json — Scheduled Retraining

Health-checks FastAPI → calls POST /retrain (timeout 600 000 ms) → checks all_success → sends status notification. Runs all 3 actor pipelines sequentially.

Manual / Webhook trigger

n8n_mlops_activation_workflow.json — MLOps Activation

Full MLOps lifecycle: health check → activate monitoring → trigger retraining → validate results → send Gmail summary report with Gemini AI-generated analysis. Uses Gmail OAuth credential.

📊 Monitoring — S13

Prometheus + Grafana + alerting.py + drift_detector.py

📈
Counter

ml_api_requests_total

Total prediction requests. Labels: actor, endpoint, status. Used to compute traffic rate per actor.

⏱️
Histogram

ml_api_request_duration_seconds

Request latency. Buckets: 0.05–60s. p95 computed by Prometheus. Labels: actor, endpoint.

🚨
Gauge

ml_api_error_rate

Rolling error ratio (0.0–1.0) per actor. Updated on every request. Alert threshold: > 10%.

🎯
Gauge

ml_api_model_confidence

Last-observed model confidence per actor. Alert threshold: < 0.75. Extracted from result dict.

Baseline Values
ActorConfidence BaselineMax Latency p95Max Error Rate
actor10.85 (static, co2 task)2.0 s10%
actor20.82 → dynamic (cancellation_probability)2.0 s10%
actor30.80 → dynamic (max predict_proba)2.0 s10%
Alert Rules
  • high_latency_p95Prometheus histogram_quantile(0.95) > 2.0 s → fires for actor1 cold-start (~37s first call)
  • high_error_rateml_api_error_rate gauge > 0.10 → rolling ratio of failed requests per actor
  • low_model_confidenceml_api_model_confidence < 0.75 → extracted from result dict key (confidence / cancellation_probability / max proba)
  • distribution_driftKS-test stat > 0.3 on recent 50 vs historical 100 predictions per actor
  • confidence_dropMean prediction value < actor baseline − 0.05 (actor1=0.85, actor2=0.82, actor3=0.80)

📉 Drift Detection

After 60+ predictions accumulate in predictions.json, run python drift_detector.py — KS-test compares newest 50 vs oldest 100 records per actor.

Drift Detection Detail

KS-Test: 2-sample Kolmogorov-Smirnov test compares the distribution of the most recent 50 predictions against the oldest 100 (baseline). Fires if ks_stat > 0.3.
Confidence Drop: Mean of all numeric prediction values compared to per-actor baseline. Fires if mean < baseline − 0.05.
Data: 228 records as of 2026-05-03 — actor1: 71, actor2: 110, actor3: 46. Actor3 approaching minimum threshold for reliable KS-test (needs ≥60).
